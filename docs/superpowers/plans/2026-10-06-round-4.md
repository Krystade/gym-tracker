## A. Fitted weekly targets

**Problem.** Targets are fixed per priority (1: 12–16, 2: 8–12, 3: 5–8, 4: 2–5 sets per muscle). With 2–3 one-hour sessions they can't add up, so Stats reads a realistic week as failure.

**Model.**
- Weekly budget `B` = sessions per week (`weeklyGoal`) × sets per session. Sets per session comes from:
  1. the program's `perSession`, if there is one;
  2. otherwise the median working sets per session over the last 8 weeks;
  3. otherwise 15.
- Yield `y` is the fractional muscle-sets one set produces: the mean of Σ`muscleVector` over the last 8 weeks' working sets, or 1.5 if there's no history.
- Capacity is `C = B × y`.
- Hand-set ("custom") tiers keep their ranges, and their muscles' midpoints come out of capacity first.
- The other tiers scale by `f = min(1, C' / Σ mid)` over their muscles. Each bound is rounded to 0.5, with `hi ≥ lo` and `hi ≥ 1`.
- Priority order is kept: tier 1 ≥ tier 2 ≥ … at the same `f`.

**Data.**
- `Profile.custom?: Tier[]`: the tiers whose `targets` were set by hand.
- Profiles saved before this have no `custom`. Any tier whose stored target differs from the default counts as custom, so an imported profile file's own targets keep winning.

**Code.**
- `fitTargets(profile, ctx)` in `domain/targets.ts` returns the effective targets plus `{ budget, perSession, sessions, yield, scale }` for display.
- App builds an effective profile (targets replaced) and passes it everywhere a profile is read: Stats bars, the program builder, Quick, and Today.
- Priorities saves through the raw store.

**UI (Stats → Priorities).**
- "Weekly sets, fitted to 2 sessions × 14 sets."
- One row per priority: "1 · 4–5 sets · auto" with Edit, or "1 · 8–10 sets · yours" with Use auto.
- Edit shows Min and Max inputs and Save.
- The priority dropdown options use the effective ranges.

**Tests.**
- Unit: scaling keeps order; custom tiers are kept and come out of capacity; there's no scaling when capacity is enough; the budget falls back through program, then history, then 15; old profiles are migrated.
- e2e: Priorities shows the fitted line, and editing tier 1 then "Use auto" round-trips.

## B. Walkthrough

- Five short cards in a bottom sheet (not a centred modal), each with Back, Next and Skip. The cards are:
  1. Today
  2. Log a set
  3. The plan
  4. History, Lifts and Stats
  5. Your data
- It shows on first visit. Seeing it, or pressing Skip, sets `localStorage['gym-tracker:walkthrough'] = 'done'`, wrapped in try/catch so it fails closed (not shown again this session).
- Data tab → "Show walkthrough" reopens it.
- The e2e config seeds the flag through `storageState`, so existing specs never see it. `walkthrough.spec.ts` clears it.
