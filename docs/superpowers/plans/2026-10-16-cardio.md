# Cardio machines

## Owner decisions (2026-10-16)

- Four machines: **Treadmill**, **StairMaster**, **Exercise Bike**, **Elliptical**. Each is gym equipment you tick on the Gyms screen, in a new **Cardio** group.
- Fields per machine. Time is required; the rest is optional.

  | Machine | Fields |
  |---|---|
  | Treadmill | time, distance, incline (negative for decline) |
  | StairMaster | time, level, floors |
  | Exercise Bike | time, distance, level |
  | Elliptical | time, distance, level, incline |

- **One entry per machine session**, with the incline or level you spent the most time at. For split segments, log a second entry.
- Distance is in **miles**.
- **Cardio is a priority**, next to the muscles. Its tier sets **minutes per week**, not sets: 1 is 60–90, 2 is 40–60, 3 is 20–40, 4 is 0–20.
- **The program builder places cardio** on days to reach the weekly minutes. You can move or remove those slots in the program editor.
- Cardio time **comes out of the session length**. In a 50-minute session, a 15-minute cardio slot leaves about 35 minutes of lifting.
- **Progression: more distance in the same time.** StairMaster aims for more floors.
- A machine with no history starts at **10 minutes, easy**. The first logged session becomes the baseline.

## Phase research

Nothing here depends on a platform question, because it's all domain logic and UI in code that already exists. These are the typical machine ranges the steppers allow, from common commercial machine specs:

| Machine | Range |
|---|---|
| Treadmill | incline −3% to 15% (decline models go to about −6%) |
| StairMaster | levels 1–20 |
| Bike and elliptical | resistance levels 1–20 |
| Elliptical | ramp incline 0–20 |

The steppers allow incline −10 to 30 and level 1 to 30, so no machine is clamped. Time and distance have no upper cap.

## Data model

`SetEntry` gets an optional field:

```ts
/** A cardio machine session: one entry per bout. Weight is 0 and reps is null; the `cardio` flag marks it. */
cardio?: { seconds: number; miles?: number; incline?: number; level?: number; floors?: number; aim?: number };
```

- A cardio entry looks like this:
  - `weight` is 0 and `reps` is null.
  - `flags` includes the new flag **`cardio`**.
  - `setNo` counts bouts on that machine that day.
- `isWorking` is still false for cardio, because it requires `reps > 0`. So e1RM, PRs, tonnage, muscle sets, `isHoldLift` and the rep-based target code all skip it without per-site changes.
- `src/domain/cardio.ts` is the new home for cardio logic:
  - `CARDIO`: name → `{ equipment, fields }`.
  - `isCardio(name)` and `isCardioEntry(e)`.
  - `fmtCardio(e)`, which reads like "20:00 · 1.25 mi · 3%".
  - `cardioTarget(entries, machine, minutes, date)`.
  - `CARDIO_TARGETS`.
  - `weeklyCardioMinutes(entries, week)`.
- `aim` is the target shown when the bout was logged, so the next target knows whether it was met.
- **CSV** (`domain/csv.ts`) gets six new columns at the end: `duration_s, distance_mi, incline_pct, level, floors, cardio_aim`.
  - They're optional on import, so older files still parse.
  - A row flagged `cardio` must have `duration_s`. Without it the row fails with "Cardio row needs duration_s".
  - Private sync writes these sets through the same `toCsv`, so the backup carries cardio with no further change.

## Parts, in order

Each part ships on its own.

### A. Equipment, catalog and logging

- In `domain/equipment.ts`, add `'treadmill', 'stair climber', 'exercise bike', 'elliptical'` to `EQUIPMENT`, plus a fifth group `['Cardio', [...]]`. Add `NEEDS` for the four catalog names, for example `Treadmill: one('treadmill')`. `gearOf` returns "cardio machine" for them.
- `domain/catalog.ts` gets a `// Cardio` block with the four names.
- **ExerciseCard** for a cardio name renders a new **`CardioForm`** instead of `SetForm`. It uses the same `Stepper` component, which moves to `ui/Stepper.tsx`.
  - Time is two steppers, minutes and seconds. Minutes step by 1; seconds step by 15 and wrap.
  - Distance steps by 0.05 mi, incline by 0.5, level by 1 and floors by 1.
  - Incline accepts negative numbers on the treadmill only. "Below 0 is decline" shows under the field when the value is under 0.
  - Each field is prefilled from the target (part C), or else from the last session on that machine.
  - The **More** fold holds the note and "Did this earlier?", the same as `SetForm`. Pain, RIR and warm-up don't apply to cardio.
  - The button reads **Log cardio**. The draft key works the same way as `SetForm`'s, so a half-typed form survives leaving the screen.
- `buildAppSet` takes an optional `cardio` and adds the `cardio` flag.
- Display:
  - `fmtSet` returns `fmtCardio(e)` for cardio entries.
  - History, Today's "done" list, a friend's view and the exercise screen all use `fmtSet`, so they need no further change.
  - The exercise screen for a cardio machine shows a **distance per session** list in place of the e1RM chart. It covers the last 10 sessions as "date · time · distance · pace".
- **Paste from notes** (`domain/notes.ts`): a line whose name matches a cardio machine reads `20 min`, `20:00`, `1.2 mi`, `5%`, `-2%`, `L8` / `level 8` and `52 floors`, in any order. Anything else on the line goes into the note.
- Not counted as a lifting set: `weeklySummary.sets` skips cardio. `calendarDays` counts a cardio entry as activity, so a cardio-only day still shows on the calendar. `weeklyMuscleSets` skips cardio entries rather than listing them as unmapped.

### B. Cardio priority

- `Profile.cardioTier?: Tier`. Missing means **4**, so existing profiles plan no cardio until you raise it, because tier 4's lower bound is 0. It syncs with the profile and is read and written by `parseProfileJson`.
- `CARDIO_TARGETS: Record<Tier, [number, number]> = { 1: [60, 90], 2: [40, 60], 3: [20, 40], 4: [0, 20] }`, in minutes per week. These are fixed, not fitted like the muscle targets.
- Stats → Priorities gets a **Cardio** row last. Its select reads "2 · 40–60 min", and below it a line reads "This week: 25 of 40–60 min".

### C. Program and progression

- `Slot` gets `minutes?: number`. A slot with `minutes` is cardio: its `sets` is 1 and `repMin`/`repMax` are unused.
- **Builder** (`buildProgram`, after the lifting pass):
  - The weekly goal is the lower bound of `CARDIO_TARGETS[cardioTier]`. Zero means no slots.
  - Slots: `n = min(days, ceil(goal / 25))`, each `max(10, roundTo5(goal / n))` minutes. These go on the days with the fewest lifting sets.
  - Machine: the cardio machine this gym has that you used most in the last 90 days. If there's no history, the first available of Treadmill, Elliptical, Exercise Bike, StairMaster. If the gym has none, there's no cardio slot, and Cardio is listed in `unavailable` like a muscle with no lifts.
  - A cardio slot always comes last in its day.
- **Time budget**: `estimateSeconds` counts a cardio slot as `minutes × 60` plus one transition. `perSessionForMinutes` already searches for the largest lifting load that fits, so cardio minutes shrink the lifting automatically.
  - A program built by sets per session, with no minutes, adds cardio on top.
  - **Quick day** gets a cardio slot only if the cardio priority is 1 or 2 and the week is still below its lower bound. The slot is the weekly shortfall, capped at a third of the quick day's minutes and at least 10, or none.
- **Editor** (`ProgramScreen`):
  - A cardio slot shows "Treadmill · 20 min".
  - − and + step the minutes by 5, with a minimum of 5.
  - × removes the slot. The editor has no Swap; "Add exercise" with a cardio machine adds a 15-minute slot.
  - Each edit marks the program as edited, as now.
- **Today**: the plan row reads "Treadmill · 20 min · aim 1.31 mi". The counter reads 0/1, then ✓. Skip and Swap work as for lifts. Swap lists only cardio machines the gym has.
- **Target** (`cardioTarget`):
  1. The last session on that machine with distance (or floors on the StairMaster) gives a pace: miles, or floors, per minute.
  2. The aim is `pace × slot minutes`, rounded up to 0.01 mi or a whole floor.
  3. If the last session met or beat its own aim, the new aim goes **2% higher**. Otherwise it repeats.
  4. Incline and level are prefilled from the last session but not pushed.
  5. With no usable history, the row reads "Easy start · 10 min" (or the slot's minutes, if that's longer), with incline 0 and level 4 prefilled.
- **Rotation and adherence**:
  - `trainedOn` counts a cardio entry, so a day where you only did the cardio slot still moves Day A to Day B.
  - `adherence` counts a cardio slot as 1 planned. It's done when an entry on that machine (or its swap) is logged that day.

## Tests

- **Unit, `cardio.test.ts`**:
  - `fmtCardio` formats each machine.
  - `cardioTarget`:
    - It scales pace to new minutes.
    - It adds 2% after a met aim and repeats after a missed one.
    - It uses floors for the StairMaster.
    - It falls back to the easy start.
  - `weeklyCardioMinutes` sums seconds within the week only.
- **Unit, `csv.test.ts`**:
  - A cardio row round-trips all five columns.
  - An old file without the columns still parses.
  - A cardio row without `duration_s` fails with its row number.
- **Unit, `program.test.ts`**:
  - Tier 2 over 3 days gives 2 × 20 min slots.
  - Tier 4 gives none.
  - A gym with no cardio machine gives none, and Cardio is listed as unavailable.
  - Cardio minutes shrink `perSession` under a minutes budget.
  - `adherence` counts a logged cardio slot.
  - `nextDay` advances after a cardio-only day.
- **Unit, `notes.test.ts`**: "Treadmill 20 min 1.2 mi 5%" and "Stairmaster 15:00 L8 52 floors" parse into cardio entries.
- **e2e, `cardio.spec.ts`** at 375 × 812:
  1. Tick Treadmill on the gym.
  2. Set Cardio to priority 2 and rebuild. Two days show a Treadmill slot.
  3. On Today, the row shows "aim".
  4. Log 20:00 · 1.30 mi · −2%. History shows "20:00 · 1.3 mi · −2%" and the plan row shows ✓.
  5. The second session's aim is 2% higher.
- **Mutation checks**:
  - Drop the 2% bump; the progression test must fail.
  - Make `trainedOn` ignore cardio; the rotation test must fail.
  - Drop the gym-equipment filter; the no-machine test must fail.
- Check at 375 px that the cardio form, with time, distance and incline, fits without scrolling sideways, and that the program row's controls fit. Render it headless and look at it.

## Not in this round

- Outdoor runs and rides.
- Calories.
- Heart rate.
- Segments inside one entry.
- Muscle credit for cardio. It counts as minutes, not sets.
- Characters reacting to cardio.

## As built (deviations)

- No Swap in the program editor (there isn't one for lifts either). Cardio is added through "Add exercise" as a 15-minute slot; Today's Swap still offers the other machines the gym has.
- `CardioData.aim` stores the aim at logging time; the CSV carries it as `cardio_aim`.
- No tier 4 cardio is planned (its lower bound is 0); a gym without a machine sets `Program.cardioUnavailable` and the editor warns.
- e2e step 5 (second session's aim) is covered by the unit tests, not e2e: it needs a past day's bout.
