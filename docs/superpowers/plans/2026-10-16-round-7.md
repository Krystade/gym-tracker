# Round 7: fixes from the research and user-story swarms, and a new tab bar

Sources: a 10-lens research swarm (108 findings, merged and checked against the code), 11 user stories run headless at 375×812 with screenshots and a judge, and a 5-proposal navigation design panel. The reports themselves stay out of the repo.

## Owner decisions (2026-10-16)

- **Progression**: the weight goes up when total reps across the working sets reach `sets × repMax − 2`. That replaces "every set hits the top".
- **Rest timer**: starts on its own when a set is saved. Its length is the learned pace for that lift, or 2:00 with no history. Nothing to fill in.
- **Test sets recalibrate**: a test set (heavy single or AMRAP) is not a working set for double progression; it resets the working weight from its e1RM.
- **Cardio tiers** keep 60–90 / 40–60 / 20–40 / 0–20 minutes, labelled as vigorous minutes.
- **Friends** keep seeing body weight and notes. No change.
- **Cardio-only days** don't count toward the sessions-per-week goal or streak. They show separately.
- **Characters** stay visible.
- **Tab bar**: Today · History · Lifts · Stats · Gym · More. More is a grouped page: Characters, Friends, Program, Photos on top; backup, account, sync and help below. The friend-request dot moves to More.

## A. Bugs (confirmed in code, most by a failing story)

1. **Undo after a synced delete is undone again by the next sync.** `restoreSet` keeps the old `seq`, and `mergeMonth` only revives a set when `seq > deletedAt`. A restore must win over the delete it undoes: stamp the restore time (a `writtenAt`, or a new `seq` if that doesn't reorder the day) and compare that. e2e on the emulator: log, sync, delete, sync, Undo, sync, reload; the set is there.
2. **Tapping a stepper caption presses −.** `Stepper` wraps its buttons in a `<label>`. Make the wrapper a `div` (the input keeps its `aria-label`). e2e: tapping "Weight" and "Reps" changes nothing.
3. **After a warm-up the next set prefills the warm-up.** `ExerciseCard` seeds from the last logged set. Seed from the last working set today, else the target. e2e: target 185 × 9, log 100 × 5 warm-up, the form shows 185 × 9, also after a reload.
4. **An app-update reload loses typed numbers and added cards.** Drafts are memory-only and `main.tsx` reloads on `controllerchange`. Persist drafts and today's added cards per profile and date (`sessionStorage` is enough: it survives a reload, and a draft only lives for the day), and put the reload off while any form is dirty, until the page is next hidden. e2e: type, add a card, reload; both survive.
5. **An invite link befriends on page load and works for anyone for 7 days.** Accept only on a tap, on a card that says what each side will see. Make tokens single-use: the accept batch deletes the token and the rules require it gone. Copy: "Works once, for 7 days." Rules get emulator tests.
6. **A new user can't set priorities.** Stats returns early with no entries, before the Priorities card. Render Priorities (with Cardio) on an empty log, and make the Program "Priorities aren't set" note a button that opens it.
7. **A lift added to a day lands after its cardio slot.** Insert lifts before the first cardio slot.
8. **Reopening the builder forgets minutes mode.** Start `mode` and `mins` from the saved program.
9. **"Deadlift" in pasted notes is logged as a Romanian Deadlift.** Add **Deadlift** (barbell) to the catalog, needs and muscles (hinge). A bare name must never fuzzy-match a more specific variant ("X" → "Romanian X").
10. **Test sets drive double progression.** See the decision above.
11. **Summary PRs use their own name key.** Use `normalizeName` as everywhere else.
12. **Cardio Seconds + wraps 45 → 0 without a minute.** Carry and borrow minutes.
13. **The cardio exercise screen ignores the planned minutes** ("Easy start · 10 min" against a 20-minute slot). Pass the day's planned minutes.

## B. Friction and visual fixes

1. Delete moves out of the Cancel/Save row in the set and cardio editors, to its own small line. Undo stays.
2. A brand-new card shows "Enter a weight" as muted help until the field is touched or Add set is tapped, not as a red error.
3. Paste review shows cardio lines like History ("20:00 · 1.2 mi · 5%"), with the as-written line.
4. Cardio charts and tiles show distances under 10 mi to one decimal, with unique axis ticks; the aim rounds to 0.1 mi. "Log this lift on two days" says "Log this on two days" for cardio.
5. An untouched incline isn't saved (no "0%"); incline starts empty like distance unless the last session had one. History counts cardio in minutes, not sets.
6. "Today so far" shows repeat counts ("50 × 10 ×2").
7. The "goal" label on the sessions chart isn't clipped.
8. With no cardio priority, Stats shows "This week: 25 min" without a range.
9. "Nothing at this gym trains …" only warns for muscles above priority 3.
10. A swapped-in hold shows its own target on the plan row; cards keep plan order instead of creation order.
11. Walkthrough card 5's ring stays inside the screen on an edge tab.
12. Invite copy: the "@" stays on usernames; spacing under the Cancel/Share row.

## C. Progression and rest timer

1. `nextTarget`: go up when total working reps ≥ `sets × repMax − 2` (each set still at least `repMin`). Unit tests cover 12/12/10 at 3 × 8–12 (up), 12/10/10 (stay), and a set below `repMin` (stay).
2. Test sets: excluded from double progression; a test set newer than the last working session sets the working weight to the weight its e1RM gives at the top of the rep range, rounded to the lift's step. Tests for both.
3. Rest timer: on save, a sticky bar counts down from the lift's learned rest (from `timing`), or 2:00. Tap to dismiss, +30 s. Keeps the screen awake while running if the Wake Lock API is there. No sound (logging happens with music on). e2e at 375px: it shows after Add set, doesn't cover the form's buttons, and goes away on the next set.

## D. Tab bar

Per the design panel's recommendation:

1. First, its own commit: an `e2e/nav.ts` helper (`goto(page, 'More' | 'Friends' | 'Gym' | …)`), with the specs that click tabs moved onto it, green on the old bar.
2. `App.tsx`: tabs `today | history | lifts | stats | gym | more`, with `friends` an internal state shown as More. `GymsScreen` renders as the Gym tab (no Back at the root; the empty state never leaves a phantom gym). The friend-request dot moves to More.
3. More = the Data screen, renamed, with a grouped list on top: Characters, Friends (with request count), Program, Photos. Each opens its existing screen with "‹ More" back.
4. Today shows "at {gym} ›" only when there are two or more gyms; it opens the Gym tab.
5. Program shows the gym line above the days, not inside the folded Rebuild section.
6. Copy: "Data tab" → "More" everywhere; walkthrough card 5 points at More, card 3 mentions Gym.
7. New `e2e/gym-tab.spec.ts`; walkthrough and friends specs updated; screenshots checked by eye at 375×812.

## E. From the owner's phone (2026-10-16, iPhone, screenshot)

1. **Content shows through the status bar.** With one profile there's no sticky profile bar, so a scrolled card title sits under the clock and battery. Add a fixed backdrop the height of `env(safe-area-inset-top)` in `--bg` above everything.
2. **The When row overlaps.** On iOS the time input keeps its own intrinsic width, so "A guess is fine" draws over it. Stack the hint under the input, and give the input `-webkit-appearance: none; min-width: 0; width: 100%` so it obeys the layout. Same fix for the cardio form's When.
3. **Editable tags.** The More fold's chips (Pain, Unsure, Warm-up, 2× pulley, Test) become a list he manages:
   - An **Edit tags** chip at the end of the row opens an inline editor: each built-in tag with a Show/Hide switch, his own tags with ×, and an "Add a tag" field.
   - Hiding a built-in only hides its chip; the flag keeps its meaning (Warm-up still isn't a working set, Pain still opens the pain fields). A set that already has a hidden tag still shows it, so it can be turned off.
   - His own tags are plain labels saved on the set as `tags?: string[]`, shown in set rows and History like flags, carried in the CSV as a `tags` column (`;`-separated) and through sync. Analytics ignore them.
   - The tag list (hidden built-ins and his own, in order) is kept per profile with the other settings, so it syncs.
   - No new required input: logging without tags is unchanged.
